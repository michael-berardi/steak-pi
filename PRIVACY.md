# Privacy

This is the fine print behind the short [Privacy section](README.md#privacy). It describes the code on this branch. Steak Pi has no telemetry, analytics, crash reporter, install ID or token/credential logging.

## Network access

- **Background check (on by default in interactive sessions).** Steak Pi makes one anonymous HTTPS GET to GitHub's public `https://api.github.com/repos/michael-berardi/steak-pi/releases/latest` endpoint, with the fixed user-agent `steak-pi-update-check` and no query parameters, at most once per 24 hours across all Pi sessions on this machine (the interval is shared through a local cache file). The request carries no account, version, prompts, paths, usage, machine IDs, unique IDs or credentials; GitHub still sees ordinary HTTPS metadata such as your IP address. Print, JSON, RPC, worker and CI runs never check. When a newer release exists the footer shows one notice line and, only when the session is idle, one dialog (Install update, Remind me later, Skip this version); nothing is installed unless you choose it, run `/steak-update` or `steak-pi update`, or turn on automatic updates (off by default). `STEAK_PI_NO_UPDATE_CHECK=1`, `steak-pi update --checks off` or `CI=true` disables it; `PI_OFFLINE=1` does **not** disable this particular check, so use the named opt-out. `steak-pi update --check` and `steak-pi update` contact GitHub only when you run them: `--check` reads the same endpoint, and an update downloads the release archive and `SHA256SUMS` and checks the archive before anything changes. See [docs/updates.md](docs/updates.md). The release installers verify a published SHA-256 checksum; install and update commands disable npm and Homebrew analytics for the toolchains Steak Pi invokes.
- **Your model provider.** Pi sends the prompts, file contents and tool results you send to whatever provider you configured. Steak Pi does not choose a provider or relay your data anywhere else.
- **Local models.** `steak-pi local add <gguf>` reads a local file. For a Hugging Face spec (`owner/repo:quant`) it queries huggingface.co for the file list and the first few MiB of the chosen quant; a local GGUF's own base-model metadata is used when looking for a harness adapter. `HF_TOKEN`, when set, is sent only to huggingface.co. An adapter found this way is downloaded only after you trust its publisher (the trust answer is local); a model or adapter you name explicitly is fetched when you ask. Downloads are pinned and checked against the hub's SHA-256; a bad file is discarded. `llama-server` downloads the weights itself on first start.
- **Google AI Ultra plan sign-in.** Only when you choose it in `/login`: the browser goes to `accounts.google.com`, a loopback server on `127.0.0.1` receives the redirect, and the code, refresh and DPoP proofs go to `oauth2.googleapis.com`. Model requests go to `generativelanguage.googleapis.com`. The refresh token and its machine-bound DPoP key are stored by Pi in `~/.pi/agent/auth.json`; `/logout` removes them.
- **Other configured network features.** A model-catalog refresh and the temporary free-route check contact their configured provider only when those features are used. `steak-pi update --models` refreshes Pi's provider catalogs when you run it.
- **Pi's own defaults.** `steak-pi run` and both installers set `PI_TELEMETRY=0` and `PI_OFFLINE=1`: the first turns off Pi's install beacon and provider attribution headers; the second stops Pi's automatic version/package checks, `fd`/`rg` downloads, model-catalog refresh from pi.dev and automatic installation of missing packages at startup. `pi install` and `steak-pi update --models` still work when you run them. Set either variable yourself to restore Pi's defaults; if you start `pi` directly, set both for the same privacy defaults.

## Local writes

Every write below has a documented lifetime plus either an automatic bound or an explicit owner-managed retention decision. Paths under `~/.pi/agent/` follow `PI_CODING_AGENT_DIR` when set; cache paths follow `XDG_CACHE_HOME` when set.

| Local write | Contents | Lifetime / automatic cleanup or retention | Delete it |
| --- | --- | --- | --- |
| Pi session transcripts (`~/.pi/agent/`, or `PI_CODING_AGENT_DIR`) | Session JSONL: prompts, tool inputs/results and assistant text. Written by Pi, not by Steak Pi. | Pi owns these files and their retention; Steak Pi adds no sweeper and `steak-pi remove` leaves them in place. | Delete the session files or the agent directory yourself. |
| Local-model config (`~/.pi/agent/models.json`, `models.json.bak-*`, `~/.pi/agent/local/profiles/`, `trusted-publishers.json`, `hold.json`) | Model ids/base URLs/launch args, publisher trust answers, hold and bypass rules. | Kept until you change them. At most 5 timestamped `models.json` backups; atomic temp files are renamed on success and removed on write error. | Edit or delete the entries/profiles and the backup or temp files. |
| Downloaded models and adapters (`~/.pi/agent/local/adapters/`, and the weights `llama-server` downloads into its own Hugging Face cache, commonly `~/.cache/huggingface/`) | GGUF weights and SHA-256-checked LoRA adapters you chose. | Reused, no expiry: one download per explicit or trusted request. Failed or mismatched adapter files are removed; GGUF header probes use a system-temp directory removed in `finally`. | Delete the adapter/model files or the Hugging Face cache. |
| Local server state (`~/.pi/agent/local/leases.json`, `server.json`, `server.log`, `server.log.1`) | PIDs, ports and start times of the server Steak Pi started, plus its stdout/stderr (no tokens or credentials). | Dead leases are pruned and `server.json` is removed when the server stops. At server start, `server.log` is rotated to a single `server.log.1` once it passes 8 MiB, so at most two log files are kept. | Run `steak-pi local stop`, then delete the files. |
| Compaction snapshots (`<project>/.steak-pi/snaps/snap-*.json`) | Full conversation entries saved before compaction; directories 0700, files 0600. | On each write, pruned to the newest 10 files and no older than 14 days. | Delete `<project>/.steak-pi/snaps/`. |
| Verification output (`~/.cache/steak-pi/verification/run-*/`) | stdout/stderr (8 MiB per run), result state and an optional native report (4 MiB); files 0600. | At the next admission, finished runs older than 7 days or beyond 32 runs are removed; the admission lock is removed after use. | Delete `~/.cache/steak-pi/verification/`. |
| Update cache and log (`~/.cache/steak-pi/update-check.json`, `update-check.json.<pid>.tmp`, `auto-update.log`) | Last check time, latest published version and any error string, 0600; the automatic-install log; no conversation data. | One cache file, overwritten at most once per 24 hours. A temp left by a killed process is swept when older than 24 hours on the next check. The log is one file capped at 256 KB. `steak-pi update --auto off` deletes the cache and log. | Delete the JSON file, its `.tmp` siblings and the log. |
| Update choices (`updates` section of `~/.pi/agent/steak-pi.json`) | Automatic-update and check switches, a skipped version, when a notice was last shown. | Kept until you change them; `steak-pi remove` deletes the section. | Run `steak-pi remove`, or delete the `updates` section. |
| USAP checkpoints (`~/.pi/agent/usap/<namespace>/`) | Run/task checkpoint JSON for resumed subagent runs. | Terminal runs capped at 50 plus 16 active; dead namespaces are swept after 7 days on store close. | Inspect and delete the namespace directory. |
| Route evidence and slot leases (`~/.pi/agent/usap/route-evidence.jsonl(.1)`, `~/.local/state/steak-pi/usap-slots/`) | Task-class route outcomes, and PID-tagged slot leases/claims. | Evidence rotates at 5 MB into one `.1` generation; dead slot holders are reclaimed, while abandoned claims fail closed rather than being guessed at. | Delete the evidence files or the slot directory (remove an abandoned `.claim` manually). |
| USAP worktrees (`~/.pi/agent/usap/<namespace>/worktrees/`, or `~/.cache/steak-pi/worktrees/` when no checkpoint store is open) | Isolated task worktrees and `.meta-*.json` receipts. | Clean worktrees are removed at task end and clean orphans after 24 hours; dirty or committed worktrees are retained for parent integration. | Remove retained worktrees/branches after integrating or discarding them. |
| Companion UI streams (`~/.ultraterm/ui-streams/<pid>.json`) | Up to 128 KiB of assistant prose per stream, 0600. | Removed when the stream ends; records of dead PIDs are swept on session start (first 256 directory entries). | Delete `~/.ultraterm/ui-streams/`. |
| Staged-runtime transpile cache (`~/.ultraterm/runtime/`) | Content-addressed runtime trees and a Jiti transpile cache used by staged workers. | Read normally; a missing cache directory is recreated on demand and holds no conversation content. | Delete the tree when no staged worker is running. |
| Session state (`<project>/.steak-pi/todo/<hash>/todo.json`, `TODO.md`, `~/.ultraterm/agent-state/<session>.json`) | Explicitly requested phased todos and companion status. | Todo state is kept for its session; its temp files are renamed on success and cleaned on error. Agent-state files are removed at session exit and dead-PID temps at startup. | Delete the todo or agent-state files. |
| Release installs and Node compile cache (`.../steak-pi/releases/<version>/package/`, `~/.cache/steak-pi/node-compile-cache/`) | Installed release code/dependencies and V8 compile cache. | One rollback release is kept, deleted after the new release has started once or seven days after it was replaced; older folders go too, but never while a known Pi agent directory pins them or an older Pi session still runs. Download staging folders are deleted on success and failure. The compile cache is disposable. | `steak-pi remove` unregisters the Pi package; delete these folders yourself if you no longer need them. |

`steak-pi remove` unregisters the Pi package and deletes the `updates` settings; it does not delete the other files above.
